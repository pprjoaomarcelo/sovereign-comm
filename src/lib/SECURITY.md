# Security Policy

## Overview

The security of the Sovereign Project is our highest priority. We appreciate the help of the security community in keeping our protocol and implementations secure.

## Reporting a Vulnerability

*Please do not report security vulnerabilities through public GitHub issues.*

Instead, please email `security@sovereign.dev` (this is an example address that we will need to set up).

Please include as much information as possible in your report, including:

- *Type of vulnerability:* (e.g., Denial of Service, Signature Forgery, etc.)
- *Affected component:* (e.g., Indexer Node, Gateway Node, Gossip Protocol, etc.)
- *Detailed description:* Steps to reproduce the vulnerability.
- *Proof of Concept (PoC):* A script or detailed instructions demonstrating the flaw.
- *Impact:* What is the impact of the vulnerability?

## Our Commitment

Upon receiving a security report, we commit to:

1.  *Acknowledge* receipt of your report within 48 hours.
2.  *Investigate* the vulnerability and confirm its validity.
3.  *Maintain open communication* with you about the progress of the fix.
4.  *Give you due credit* when the fix is released, unless you prefer to remain anonymous.

## Disclosure

We ask that you do not publicly disclose the vulnerability until we have had the opportunity to analyze and fix it. We will coordinate disclosure with you to ensure our users are protected.

We appreciate your help in keeping the Sovereign Project secure.
